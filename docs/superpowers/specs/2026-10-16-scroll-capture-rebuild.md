# 长截图采集流程重构

用户要求参照 https://github.com/lzhgus/Capso 改善长截图可用性与稳定性，并已明确批准本会话后续操作。采用架构重构路径，直接推进设计、实现和验证；不再逐项请求批准。

## 调查与选择

现有 FreeMouse 每 20ms 投递自动滚动，任何积压帧的成功拼接都会清空滚动预算，无法证明该帧已经反映最新滚动。结束时停止消费者后固定等 180ms，再停源排空；在此期间缓存可能溢出且末尾不能重取。原生帧在检查缓存容量前就完整转换，即使已经过载也继续消耗转换资源。

参考 Capso 的串行采集、成功才更新参考图、明确完成操作和轻量浮层。Capso 当前手动采集为主，Vision 平移估计没有现有 FreeMouse 的误拼接保护；直接替换会丢失固定侧栏、重复文字及真实帧回归保障。因此选择重构采集协调，保留独立的像素匹配与输出实现。另一选择仅改匹配阈值无法解决采集时序，整套移植又引入不必要回归。独立实现，不复制 BSL 1.1 源码。

## 行为与边界

- macOS 15+，Swift/AppKit/ScreenCaptureKit，不新增第三方依赖。
- 默认手动滚动；暂停不会结束，自动滚动仍需辅助功能权限；保留复制、保存、编辑、OCR、取消。普通 Return/Space/O 仅控制条聚焦时生效；全局输出改用 Ctrl+Option+Command+对应键，避免干扰其他应用输入；Esc仍全局取消。
- 自动滚动每次最多 20% 视口，小选区保留至少 20 个物理像素重叠。每步必须等到投递之后采集的成功匹配帧，并留出页面响应时间，再发送下一步；积压帧不能提前确认。无响应/持续无法匹配则停止自动并保留已有内容。
- 处理积压或无最新帧时不继续发送自动滚动。用户手动接管、暂停、完成、取消立即停止投递。
- 原生帧转换之前检查会话、暂停和缓存预算；拒绝帧仍记录序号缺口，不覆盖已接受桥接帧。在途转换也计入待处理状态，避免结束时提前封流。保持 8 帧/2400万像素缓存预算，长图输出不增加尺寸上限。
- 完成阶段继续消费帧，至少等待 300ms，且距最后一次图像追加/拒绝已安静 250ms 后结束稳定等待阶段，最多等待 2s；尚有缓存时继续排空。随后用同一选区、窗口排除和分辨率调用原生单次截图，核对流可能延迟交付的最终画面。系统截图失败、稳定等待超时或未确认缺口必须保留不完整提示。取消不能输出，旧会话不能污染新会话。
- 手动暂停直接停用帧转换；恢复保留已拼接参考，并等待新画面。暂停时舍弃的排队/转换/组装在途帧，以及暂停期间收到的新 complete 样本，都标记末尾待确认；不局限于滚轮事件，涵盖键盘、拖动滚动条及页面自身变化。停止原生流之前保存缺口状态，避免 teardown 清零后误报完整。暂停完成时原生截图只作逐像素核对，不追加画面；完全相同才能证明已截视口仍是当前画面。
- 预览明确显示已采集帧数、尺寸与当前状态；匹配失败保留结果并给出恢复操作，成功接回后清除提示。
- 所有图像在本机处理，诊断仍仅由用户主动导出；不访问凭据，不更换已安装应用。

## 验证

基线与最终完整 Swift Testing 回归；新增纯状态测试覆盖旧帧确认、等待后再滚、无变化超时、暂停/接管、尾帧超过180ms、连续尾帧超时、缓存转换门控与缺口记录。保留全部像素匹配、真实非私人样本、超长输出测试。独立代码审查与 Release 构建。使用 scripts/scroll-validation 的独立合成窗口，实际验收流采集与控制器完成/取消/暂停；已有辅助功能权限时验收自动滚动。真实屏幕采集若受系统权限或自动化环境限制，明确报告，不把离线测试冒充实际应用验收。最终文件、日志、构建与交付包仅写当前项目目录，构建产物位于 .build，交付包位于 outputs。
